## Fixes

- Ticks skip projects with an active or queued rolling run. Previously, the last published position could make the commit already being built look due again. The queued workflow would later find an empty matrix. Active runs are now queried separately with pagination, so a long run cannot disappear behind the 300 most recent runs.
- Upstream fetch failures fail the tick for that project without dispatching it. Other projects are still checked. Failed completed runs are flagged even when no new commit is due.
- The scheduler checks out current `main` and refreshes results after setup. The project planner reports an empty selection in its Actions summary, and a failed planner cannot start publication.
- Reports exclude experimental lanes, including older records written before the experimental flag existed. Matching now accounts for lanes with no passing steps and requires the same source SHA across the compared lanes.
- Rolling dispatches require the canonical tool title so `cargo` and `Rust/Cargo` cannot bypass each other's workflow lock. Superseded step reruns are removed from the matrix, and a failed fetch cannot bypass the phase's newer-step guard.
- New records distinguish a tracked Actions cache restore from providers that do not expose a restored key. A tracked scope that has never restored is now reported as unseeded after its first step. Historical records without that distinction retain the earlier inference from observed restores.
- CI now runs actionlint 1.7.12 using the [official release](https://github.com/rhysd/actionlint/releases/tag/v1.7.12), pinned by version and archive checksum.
- A new hourly report workflow generates `data/results.json` and `data/report.md`. It uses its own schedule because result commits made with `GITHUB_TOKEN` do not trigger ordinary push workflows: [GitHub trigger rules](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow).

A manual dispatch can still race a scheduler check. The project planner rechecks the recorded position and may produce an empty selection in that situation. Projects with a stride greater than one wait until that many first-parent commits are available. If every lane fails before recording a result, the next tick retries the same position; that case needs a setup-failure investigation.

## Claude Fable cross-check

Claude Fable reviewed the repository independently and then reviewed the scheduler and report code supplied for a second pass. Its stale-results, alias/concurrency, failed-fetch guard, missing publisher, obsolete tooling, and never-restored-cache findings were checked against the code and addressed.

Some suggestions were not adopted: the existing cache-prune guard already preserves older step caches unless the new step exists, and rescuing every Ruby exception would hide programming errors. Case-only input differences already share GitHub concurrency groups and are matched case-insensitively by the tick.

Residual conditions to investigate when they occur: a run cancelled after saving caches but before publishing results can leave the rolling cache ahead of the recorded cursor; all-lane setup failures leave no record and can repeat at the same commit. Upstream history rewrites also need operator review. This change does not claim to repair those cases or to validate every provider build.
